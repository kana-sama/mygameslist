# Заметки-тирлисты

В редакторе заметки выберите **Тирлист** в списке форматов. Новая заметка
по-прежнему начинается с Markdown. Пустой тирлист можно сохранить; готовых
грейдов приложение не создаёт.

Введите необязательное название и добавьте грейды с любыми непустыми названиями.
Новый грейд появляется строкой в конце доски. Название изменяется прямо в левой
ячейке: Enter или уход фокуса сохраняет его, Escape отменяет. Пустое название
показывает локальную ошибку; одинаковые названия разрешены. Грейды перемещаются
за тихий маркер рядом с названием. Удаление непустого грейда требует подтверждения,
поскольку вместе с ним удаляются карточки.

В конце каждого грейда находится квадрат с плюсом. Рамка и фон квадрата
появляются при наведении на грейд или фокусе клавиатуры внутри него. Нажатие
открывает модальное окно: общий выбор изображения сверху, редактор Markdown
снизу. Изображение и текст необязательны по отдельности, но пустую карточку
сохранить нельзя. Нет отдельного типа карточки или поля названия.

Изображение можно выбрать файлом, перетащить в общий picker, вставить из буфера,
заменить или убрать. Приложение обрабатывает его как обложку: вырезает квадрат
по центру и сохраняет **512 × 512 WebP**. Обычные изображения заметок продолжают
использовать свой прежний алгоритм. Ошибка подготовки или квоты не теряет
Markdown; пока изображение обрабатывается, сохранение карточки и заметки
заблокировано. Поздний результат отменённой обработки не меняет черновик.

Все карточки и квадраты добавления имеют размер **150 × 150 CSS px**, включая
рамку. Карточки переносятся по ширине грейда. Если есть изображение, на карточке
видно только его. Иначе виден первый Markdown-заголовок; для текста без заголовка
используется первая непустая строка. Нажатие на карточку с текстом открывает
обычный rich Markdown tooltip со ссылками и форматированием. Наведение или
фокус сами по себе его не открывают. Escape закрывает tooltip и возвращает
фокус на карточку. Тихая кнопка изменения у карточки открывает
тот же редактор. Escape, фон модального окна и отмена закрывают его, отбрасывают
локальные изменения и возвращают фокус. Отмена всей заметки возвращает её
сохранённую версию.

Карточки можно перетаскивать внутри грейда и между грейдами, включая пустые.
Мышью перенос начинается после небольшого движения; на сенсорном экране —
после удержания. Для клавиатуры: Space захватывает карточку, ←/→ меняют позицию,
↑/↓ выбирают соседний грейд, Home/End выбирают край, Space/Enter отпускают,
Escape отменяет. На маркере грейда Space/Enter захватывает строку, ↑/↓ или
Home/End выбирают её место, Space/Enter отпускают, Escape отменяет.

Отпускание вне доски отменяет перенос. Место вставки отмечается линией; отпускание
не открывает tooltip или редактор. В редакторе меняется черновик; в сохранённой
заметке выполняется одно автосохранение. Пока оно идёт, новые переносы блокируются.
При ошибке возвращается прежний порядок, появляется сообщение, перенос можно
повторить. Если за время сохранения источник обновился, используется его новая
версия. После переноса фокус остаётся на перемещённой карточке или маркере грейда.

Markdown и граф используют общий текстовый черновик, как прежде. Тирлист имеет
отдельный черновик, включая изображения карточек: при возврате к формату
содержимое восстанавливается. Сохраняется выбранный формат. Новые изображения
из неактивного черновика тирлиста не становятся вложениями Markdown-заметки;
исходные изображения текстовой заметки сохраняются и при совпадении SHA.

## Исходники и изображения

В метаданных заметки используется `format: tierlist`; её существующее поле
`bodyMarkdown` и файл `.md` содержат JSON версии 2:

```json
{
  "version": 2,
  "title": "Пример",
  "grades": [
    {
      "id": "grade-1",
      "name": "Произвольный грейд",
      "cards": [{ "id": "card-1", "imageAssetId": null, "bodyMarkdown": "# Карточка\n\nОписание" }]
    }
  ]
}
```

Порядок задают массивы. ID грейдов и карточек уникальны и стабильны. Каждая
карточка содержит ровно `id`, `imageAssetId` и `bodyMarkdown`. `imageAssetId` —
`null` либо lowercase SHA-256 ID существующего image asset; у заметки обязательно
есть соответствующее image attachment. В браузерном черновике вместо него до
сохранения может быть `pending-image` с подготовленным blob и тем же SHA.
Отдельного хранилища карточек нет.

Строгая версия 1 остаётся читаемой. Её типы `text`, `image` и `image-text`
преобразуются в единые карточки в памяти; прежний буквальный текст экранируется,
чтобы его Markdown-символы сохранили видимый смысл. Само чтение не переписывает
файл. Версия 2 записывается только после явного изменения тирлиста.

Изображения, используемые карточками, скрыты из обычной галереи вложений.
При удалении последней ссылки карточки её запись пула убирается из заметки;
остальные ссылки на то же изображение, изображения других заметок и несвязанные
вложения сохраняются. Оптимизация, хранение blob, экспорт/импорт патчей,
сборка исходного дерева и сборка мусора используют существующий asset pipeline.

Неверный JSON, версия, поля, повторные ID, пустые карточки или отсутствующие
image attachments показывают ошибку. Тирлист не участвует в поиске
Markdown-задач и не считается чеклистом для прогресса. Review показывает смену
формата и текстовый diff JSON.
