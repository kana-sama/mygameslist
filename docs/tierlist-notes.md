# Заметки-тирлисты

В редакторе заметки выберите **Тирлист** в списке форматов. Новая заметка
по-прежнему начинается с Markdown. Пустой тирлист можно сохранить; готовых
грейдов приложение не создаёт.

Введите необязательное название, добавьте грейды с любыми непустыми названиями.
Названия могут совпадать. Кнопки рядом с грейдом переименовывают, перемещают
выше/ниже и удаляют его. Удаление непустого грейда требует подтверждения,
поскольку вместе с ним удаляются карточки.

**Добавить карточку** открывает форму. Выберите текст, картинку или картинку
с текстом. Картинку можно загрузить локальным файлом либо взять из уже
прикреплённых изображений. Тип можно менять, не теряя введённые поля в форме.
Сохраняются только поля выбранного типа. Ошибка загрузки сохраняет текст;
во время подготовки изображения сохранение карточки и заметки заблокировано.
Кнопка ✎ у карточки открывает изменение и удаление. Отмена формы оставляет
тирлист прежним; отмена всей заметки возвращает её сохранённую версию.

Все карточки имеют размер 80 × 80 CSS px и переносятся внутри грейда по ширине
заметки. Изображение кадрируется по центру только при отображении. У картинки
с текстом подписи нет: полный текст открывается наведением, фокусом клавиатуры
или нажатием на сенсорном экране.

Карточки можно перетаскивать внутри грейда и между грейдами, включая пустые.
Мышью перенос начинается после небольшого движения, на сенсорном экране —
после удержания. Для клавиатуры: Space захватывает карточку, ←/→ меняют позицию,
↑/↓ выбирают соседний грейд, Space/Enter отпускают, Escape отменяет.
Отпускание вне грейдов тоже отменяет перенос. Место вставки отмечено линией.
В редакторе меняется черновик; в сохранённой заметке выполняется одно
автосохранение. Пока оно идёт, новые переносы блокируются. При ошибке
возвращается прежний порядок, появляется сообщение, перенос можно повторить.

Markdown и граф используют общий текстовый черновик, как прежде. Тирлист имеет
отдельный черновик, включая изображения карточек: при возврате к формату
содержимое восстанавливается. Сохраняется выбранный формат. Новые изображения
из неактивного черновика тирлиста не становятся вложениями Markdown-заметки;
исходные изображения текстовой заметки сохраняются и при совпадении SHA.

## Исходники и изображения

В метаданных заметки используется `format: tierlist`; её существующее поле
`bodyMarkdown` и файл `.md` содержат JSON версии 1:

```json
{
  "version": 1,
  "title": "Пример",
  "grades": [
    {
      "id": "grade-1",
      "name": "Произвольный грейд",
      "cards": [{ "id": "card-1", "type": "text", "text": "Карточка" }]
    }
  ]
}
```

Порядок задают массивы. ID грейдов и карточек уникальны и стабильны. Тип `text`
содержит `text`, тип `image` — `imageAssetId`, тип `image-text` — оба поля.
Текст обычный, без Markdown. `imageAssetId` — lowercase SHA-256 ID существующего
image asset; у заметки обязательно есть соответствующее image attachment.
В браузерном черновике вместо него до сохранения может быть `pending-image`
с подготовленным blob и тем же SHA. Отдельного хранилища карточек нет.

Изображения, используемые карточками, скрыты из обычной галереи вложений.
При удалении последней ссылки карточки её запись пула убирается из заметки;
остальные ссылки на то же изображение, изображения других заметок и несвязанные
вложения сохраняются. Оптимизация, хранение blob, экспорт/импорт патчей,
сборка исходного дерева и сборка мусора используют существующий asset pipeline.

Неверный JSON, версия, поля, повторные ID или отсутствующие image attachments
показывают ошибку. Тирлист не участвует в поиске Markdown-задач и не считается
чеклистом для прогресса. Review показывает смену формата и текстовый diff JSON.
