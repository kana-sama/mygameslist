# Графовые заметки

Точный контракт исходного текста, включая все атрибуты, значения по умолчанию,
экранирование, ограничения и правила генерации, вынесен в
[полную спецификацию формата](graph-format-spec.md).

Внизу редактора выберите **Markdown** или **Граф**. Новая заметка всегда начинается
с Markdown; старые заметки без `format` также остаются Markdown. Переключение
меняет интерпретацию, сохраняя текст без преобразования. Отмена восстанавливает
исходный формат и текст. В пустом графе кнопка **Вставить пример** добавляет пример
только по вашему нажатию. Ошибки показываются в Monaco и под редактором со строкой
и столбцом; до их исправления сохранение, включая Ctrl/Cmd+Enter, недоступно.
Вложения, порядок и двойная ширина/высота работают как у Markdown-заметок.

```dot
digraph {
  label="Путь к храму";
  start [label="Найти карту", state=done];
  subgraph forest {
    label="Лес";
    key [label="Добыть ключ", subtitle="Северный лес", kind=special];
    shrine [label="Открыть храм", kind=milestone, state=doing];
    hint [label="Вход с севера", kind=note, task=false];
    key -> shrine [label="открывает"];
  }
  start -> key;
  subgraph side_stories {
    label="Самостоятельные истории";
    kind=section;
    layout=grid;
    island [label="Остров"];
    valley [label="Долина", subtitle="Южная область"];
  }
}
```

## Поддерживаемый DOT

Разрешён один `digraph`, с именем или без. Пустой текст и `digraph {}` — пустой
граф. Узлы объявляются явно (`a;` или `a [label="Задача"];`), ровно один раз.
Идентификаторы узлов и именованных `subgraph` уникальны во всём документе,
чувствительны к регистру. Каждый узел принадлежит одному непосредственному
контейнеру. Допускаются обычные идентификаторы и строки в двойных кавычках с
Unicode; экранирование `\"`, `\\`, `\n`. Точки с запятой
необязательны, атрибуты разделяются запятыми или точками с запятой. Комментарии:
`// до конца строки` и `/* несколько строк */`.

Связи направленные: `a -> b`, цепочки `a -> b -> c`. Концы связей могут ссылаться
на узлы и группы до объявления и через границы контейнеров. Связь с группой
касается её границы; она не превращается в связи со всеми детьми. Циклы,
самоссылки и несвязанные компоненты допустимы. Нельзя соединять секции, пустые
группы и пару предок/потомок с неоднозначной границей.

| Объект | Атрибуты и значения |
| --- | --- |
| Корневой граф | `label` — необязательное название заметки |
| Подграф | `label`; `kind=group\|section` (по умолчанию `group`); `layout=flow\|grid` (по умолчанию `flow`) |
| Узел | `label` (по умолчанию идентификатор); `subtitle`; `kind=normal\|special\|milestone\|note` (по умолчанию `normal`); `task=true\|false` (по умолчанию `true`); `state=todo\|doing\|done` (по умолчанию `todo`) |
| Связь | Необязательный текст `label` |

Все узлы по умолчанию задачи (`task=true`), независимо от `kind`. Для
информационного узла задайте `task=false`; явный `state`
при `task=false` недопустим. Значения `label` и `subtitle` — обычный текст;
HTML-подобный текст внутри кавычек отображается буквально.
На уровне графа и подграфа допустимы прямые присваивания (`label="Лес"`) или
`graph [label="Лес"]`; повтор атрибута — ошибка.

Другие конструкции DOT и неизвестные атрибуты запрещены, включая визуальные
стили, цвета, координаты, шрифты, HTML-метки, URL, изображения, порты, `strict`,
ненаправленные связи и общие настройки `node [...]` / `edge [...]`.

## Группы и размещение

`group` — мягкий контейнер с необязательным заголовком. Без `label` техническое
имя не выводится. Группы могут быть вложенными. `section` существует только в
корне, требует непустого названия, занимает всю доступную ширину и отображается
без окружающей карточки или рамки.

`flow` размещает узлы по связям; `grid` сохраняет порядок непосредственных детей
в сетке до трёх колонок. Связи внутри сетки остаются видимыми. Независимые корневые
компоненты размещаются по авторскому порядку максимум в двух колонках, секции
занимают отдельную полную строку. Связанные корневые группы остаются вместе.
При сужении колонки сокращаются и подписи переносятся. Минимум основного текста —
11 px, подзаголовка — 10 px; если граф всё ещё не помещается, прокрутка остаётся
внутри заметки. Пользователь задаёт структуру; цвета, отступы и геометрию задаёт
приложение. Сбой или таймаут расчёта (5 секунд) допускает повтор без потери текста.

Простая цепочка узлов в `flow` идёт слева направо: карточки делят внутреннюю ширину
группы, секции или корневого графа с учётом промежутков. Ширина карточки — от
116 до 220 px; подписи переносятся, шрифты и чекбоксы сохраняют размер.
Если минимальная ширина не помещается, цепочка остаётся вертикальной.
Сами контейнеры групп ради строки не сужаются. Цепочки со связями с подписями,
включая внешние связи, сохраняют вертикальное размещение для текста связей.
Ветвления, циклы, самоссылки и явная сетка сохраняют обычное размещение.

Автоматические переносы выравнивают длину строк; слово с числовым суффиксом
(например, «Глава 2») остаётся вместе, если помещается в строку. Явные переносы
и пустые строки сохраняются; неразрывные пробелы удерживают помещающуюся связку.

## Выполнение задач

Щелчок или Space: `todo → done`, `doing → done`, `done → todo`.
Shift+щелчок (или Shift+Space): переключение частичного состояния `doing/todo`.
Связи не блокируют задачи и не выполняют соседние узлы автоматически.

Чекбокс группы/секции учитывает всех потомков-задачи один раз. Он отмечает всех
выполненными одним сохранением; повторное нажатие у выполненной группы возвращает
их в `todo`. Информационные узлы не меняются. Полностью выполненная непустая
группа отмечена галочкой, частичное выполнение или `doing` — промежуточным
состоянием. Пустые и информационные группы не получают чекбокс или счётчик `0/0`.

Выполненные узлы и связи остаются видимыми, включая режим скрытия выполненных
Markdown-пунктов. Фокус и прокрутка сохраняются; параллельные записи одной заметки
блокируются. Ошибка сохранения восстанавливает исходные состояния и допускает
повтор. При записи меняется только атрибут `state`: комментарии, пробелы и
порядок прочего текста сохраняются. Название корневого графа используется в
ссылках, выборе заметки для прогресса и проверке изменений. Поиск по Markdown-
чеклистам, Markdown-ссылки на игры и rich tooltip в графах не обрабатываются.

## Ограничения и хранение

Максимум: **100 KiB UTF-8**, **300 узлов**, **600 связей**, **50 подграфов**,
**8 уровней вложения**, **500 символов** в каждой подписи/подзаголовке.
Превышение — явная ошибка, содержимое не обрезается.

В исходных файлах сохраняются существующее расширение `.md`, оболочка документа
и поле `bodyMarkdown`; для графа метаданные содержат `format: graph`. Отсутствие
`format` означает Markdown; каноническое сохранение Markdown опускает это поле.
Формат проходит через локальные правки, импорт/экспорт патчей и публикацию вместе
с текстом. Граф проверяется как итоговый документ. Проверка изменений показывает
экранированный исходный текст и отдельное изменение формата, без Markdown-рендера.
