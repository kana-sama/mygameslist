# Спойлеры, привязанные к чекбоксам

## Цель

Связать спойлер, являющийся всем текстом Markdown-задачи, с её чекбоксом: закрытая задача скрывает текст, а отмеченная всегда показывает его.

## Распознаваемые формы

Функция действует только для двух форм, где после маркера задачи находится ровно один спойлерный сегмент, не считая окружающих пробелов:

```markdown
- [ ] ||текст||
```

```markdown
| Этап | [ ] ||текст|| |
```

Существующий обычный спойлер внутри дополнительного текста, например `- [x] Префикс ||текст||`, не раскрывается автоматически.

## Поведение

- Пока чекбокс не активен, сегмент остаётся обычным закрытым спойлером и раскрывается по намеренному нажатию пользователя.
- При активном чекбоксе сегмент всегда отображается без размытия, включая первоначальный рендер уже отмеченной задачи.
- При переключении закрытой задачи в активное состояние текст раскрывается сразу после обычного обновления Markdown.
- Если задача была показана только благодаря активному чекбоксу, снятие отметки снова скрывает её.
- Если пользователь явно раскрыл закрытую задачу нажатием, это локальное раскрытие действует до размонтирования так же, как у обычного спойлера.
- Новое состояние не сохраняется: персистентным остаётся только существующий `[ ]`/`[x]` в Markdown.

## Реализация

Общий inline-модуль экспортирует проверку «строка состоит из одного спойлера». Рендер списка и таблицы передаёт в существующий компонент спойлера принудительное раскрытие только когда эта проверка истинна и соответствующий чекбокс активен. Собственное состояние явного нажатия спойлера остаётся независимым.

## Проверка

Компонентные тесты охватывают первоначально активные и неактивные формы списка и таблицы, раскрытие после переключения, повторное скрытие после снятия отметки, явное раскрытие кликом и отсутствие автоматического раскрытия у смешанного текста.
