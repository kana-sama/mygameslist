# Фреймворк смарт-заметок

Дата: 2026-10-21. Статус: согласовано пользователем, реализация поручена через субагентов.

## Назначение и согласованные ограничения

Смарт-заметка — уникальная интерактивная заметка конкретной игры. Она содержит
название, произвольный JSON-стейт, обязательный скрипт превью, необязательный
скрипт большого представления и список используемых изображений.

Сервис предоставляет только общий контракт монтирования, хранения и работы
с изображениями. Ему неизвестны структура и назначение конкретного стейта,
алгоритмы обработки изображений и интерфейс заметки. Новый экземпляр добавляется
файлами в папке игры без регистрации в коде приложения и без изменений `src/`.
Скрипты — обычные браузерные ES-модули на JavaScript с собственными HTML и CSS.
Оба представления могут читать и менять один стейт. Код загружается лениво.

Код и создание заметки редактируются в репозитории. Отдельную смарт-заметку
нельзя удалить через сайт или преобразовать в другой формат. Игру можно удалить
вместе со всеми её смарт-заметками: после синхронизации файлы исчезают из текущего
дерева, но остаются в истории репозитория.

Ссылки на загруженные изображения имеют вид `{"$asset": "<sha256>"}`. Сервис
автоматически выводит из них список ассетов и определяет ненужные изображения.
Пример карты Barbuta используется только для оценки достаточности API; сама
карта, её сетка, обработка скриншотов и специфические поля не входят в эту работу.

## Принятые решения

- Успешный вызов записи сразу сохраняет состояние в локальные правки. Общего
  черновика большого окна и кнопок «Сохранить / Отмена» нет. Публикация происходит
  существующей синхронизацией. Автор скрипта может держать незавершённый ввод
  в памяти до вызова API.
- Представления монтируются в собственные Shadow DOM с переданным DOM-контейнером.
- Большое представление — модальное окно с отступом 24 CSS px от краёв при ширине
  окна больше 680 px; на меньшей ширине оно занимает весь экран.
- Заголовок и исходный код изменяются в репозитории. Через оболочку сайта остаются
  доступными существующие настройки порядка, группы, двойной ширины и высоты.

Остальные разделы конкретизируют эти предложения и согласованные ограничения.

## Файлы и документ заметки

```text
data/games/<game-slug>_<game-id>/
  game.yaml
  notes/                         # существующие обычные заметки
  smart-notes/<note-id>/
    note.json                    # метаданные, точки входа, state, assets
    preview.js
    page.js                      # только при наличии большого представления
    ...                          # собственные JS, HTML, CSS, статические ресурсы
  assets/                        # изображения из API, общий механизм игры
```

ID смарт-заметки — стабильный UUID из общего пространства ID заметок. Он совпадает
с именем её директории. Принадлежность игре определяется родительской папкой.
Название не участвует в пути заметки. Каждая папка содержит собственную программу;
общего каталога типов, шаблонов или переиспользуемых пакетов заметок нет.

Пример минимального документа; поля стейта в примере не имеют значения для хоста:

```json
{
  "format": "smart",
  "version": 1,
  "apiVersion": 1,
  "id": "6ce72042-e2cf-4d5e-bc68-477170288465",
  "title": "Моя интерактивная заметка",
  "entrypoints": {
    "preview": "preview.js",
    "page": "page.js"
  },
  "rank": 1024,
  "createdAt": "2026-10-21T00:00:00.000Z",
  "updatedAt": "2026-10-21T00:00:00.000Z",
  "state": {},
  "assets": []
}
```

`title` обязателен и непустой. `entrypoints.page` отсутствует у заметки без
большого представления. `groupRank`, `doubleWidth` и `doubleHeight` сохраняют
существующую семантику заметок. Стейт хранится структурированным JSON, без
кодирования строкой в Markdown. Старые заметки не мигрируют и не меняют формат.

Пути точек входа относительны папке заметки и должны вести к существующим `.js`
файлам внутри неё. В исходном дереве разрешены вложенные обычные файлы и папки;
симлинки, выход за пределы директории и коллизии путей отклоняются. Остальные
файлы, кроме корневого `note.json`, считаются статическими файлами программы.

`assets` — отсортированный по ID список метаданных изображений, на которые
ссылается стейт: `assetId`, `originalName`, `alt`. Байты, размер, размеры в пикселях
и проверка SHA используют общий механизм image assets. Список автоматически
пересчитывается при записи; исходный документ с отсутствующими, лишними,
повторными или несовместимыми метаданными отклоняется при валидации.

Изображения из API хранятся в существующем `assets/` игры и дедуплицируются
по содержимому. Статические ресурсы рядом со скриптами принадлежат программе:
они публикуются вместе с ней и не участвуют в сборке мусора загруженных изображений.

## Граница приложения и скрипта

Каждая точка входа экспортирует один метод:

```js
export async function mount(root, api) {
  // Собственные DOM, события, HTML, стили и работа с API.
  return () => {
    // Освободить собственные обработчики, таймеры и другие ресурсы.
  };
}
```

Допустим и синхронный `mount`. Результат — функция очистки или `undefined`.
`root` — обычный HTMLElement внутри отдельного открытого ShadowRoot. Превью
и большое представление имеют разные контейнеры, но доступ к одной записи.
React, внутренний store, роутер, структура компонентов и внутренние CSS-классы
приложения в контракт не входят.

Скрипт управляет DOM только внутри своего контейнера; заголовок и оболочка окна
принадлежат хосту. Стили загружаются внутрь соответствующего Shadow DOM.
Шрифт и основной цвет наследуются; дополнительные стили задаёт сама заметка.
HTML/CSS можно загружать через стандартный `fetch(new URL(..., import.meta.url))`,
а вспомогательные модули — относительными импортами. Хост не исполняет `<script>`
из HTML-шаблонов и не предоставляет специальный шаблонизатор или сборку npm-зависимостей.

Это архитектурная граница для доверенного кода из репозитория. Shadow DOM
изолирует стили и DOM-структуру, но не является песочницей для JavaScript и
не запрещает доступ к глобальным браузерным API. Изоляция недоверенного кода
в iframe не входит в первую версию. Основание: [описание Shadow DOM в MDN](https://developer.mozilla.org/en-US/docs/Web/API/Web_components/Using_shadow_DOM).

## API первой версии

У каждого вызова `mount` свой объект API, ограниченный идентичностью этой заметки
и сроком жизни этого представления. Идентификатор чужой заметки нельзя передать
в методы API. Контракт содержит:

| Метод или поле | Назначение |
| --- | --- |
| `api.version` | Версия контракта, `1` |
| `api.mode` | `preview` или `page` |
| `api.signal` | AbortSignal срока жизни монтирования |
| `api.state.get()` | Независимый снимок `{ value, revision }` текущего стейта |
| `api.state.subscribe(listener)` | Слушать успешно сохранённые снимки; возвращает отписку |
| `api.state.update(reducer)` | Синхронный reducer получает копию актуального стейта и возвращает новый JSON; Promise завершается после сохранения |
| `api.state.set(value, { expectedRevision })` | Заменить стейт целиком при совпадении ревизии; иначе ошибка конфликта |
| `api.assets.list()` | Метаданные сохранённых изображений этой заметки |
| `api.assets.read(ref)` | Получить Blob изображения |
| `api.assets.url(ref)` | Получить `{ url, release }` для отображения; URL не записывается в JSON |
| `api.assets.upload(blob, { name, alt })` | Подготовить изображение и получить `AssetRef` с временным удержанием |
| `api.assets.release(ref)` | Снять временное удержание загрузки этим представлением; сохранённую ссылку не удаляет |
| `api.page.open()` | Открыть большое представление; при его отсутствии возвращает `false` |
| `api.page.close()` | Закрыть большое представление этой заметки |

`subscribe` не вызывает слушателя немедленно: начальное состояние берётся через
`get`. API снимает все оставшиеся подписки и освобождает выданные им URL при
размонтировании. Автор освобождает созданные им самим ресурсы в cleanup.

Запись не допускает `undefined`, функций, циклов, BigInt, нечисловых чисел и
других значений, не представимых обычным JSON. Ревизия — непрозрачный токен,
валидный для текущего сохранённого состояния и версии программы; скрипт не
вычисляет его сам.
Хост проверяет только общий JSON-контракт и ссылки на изображения. Валидация
предметной структуры и её миграции принадлежат программе заметки.

## Сохранение и одновременная работа представлений

Превью и страница читают один актуальный стейт. Записи сериализуются; reducer
выполняется над последним сохранённым состоянием в момент обработки операции.
Reducer не может быть асинхронным и не должен выполнять побочные эффекты.
Подготовка изображения выполняется до записи; добавление его ссылки — внутри
короткого reducer. Полная замена проверяет `expectedRevision` и не затирает
более свежие изменения.

Одна успешная операция атомарно сохраняет стейт, выведенные ссылки на ассеты,
необходимые метаданные и время изменения. После этого получают уведомление
оба представления. Мутация объекта, полученного через `get`, ничего не сохраняет.
Запись семантически того же стейта не меняет timestamp и не создаёт новую правку.
На ошибке квоты, конфликте вкладок, ошибке валидации или записи Promise отклоняется;
предыдущее сохранённое состояние остаётся действующим, а повторная попытка возможна.

Используются существующие local patch, проверка смены источника правок,
восстановление, экспорт/импорт, undo и журнал публикации. Конфликт другой вкладки
обнаруживается до записи; автоматического слияния неизвестной структуры стейта нет.
Принудительная перезапись при конфликте не допускается.

Записи, которые ещё не начали сохраняться к моменту размонтирования, отменяются.
Уже начавшаяся атомарная запись завершается целиком или отклоняется целиком.
Закрытие страницы не отменяет ранее сохранённые изменения. После удаления игры
новые операции её заметок отклоняются, оба представления размонтируются.

## Изображения и сборка мусора

`AssetRef` — объект ровно с одним полем `$asset`, содержащим SHA-256 изображения.
Поле `$asset` зарезервировано: неверный ID или дополнительные поля в таком
объекте считаются ошибкой. Массивы и обычные JSON-объекты обходятся рекурсивно;
повторные ссылки объединяются. Обычная строка с ID или URL ссылкой не считается.
Фреймворк не интерпретирует никакие другие ключи стейта.

`upload` принимает браузерный File/Blob изображения, в том числе результат Canvas.
`name` — непустое исходное имя файла, `alt` — необязательная подпись, по умолчанию
пустая. При одинаковых байтах действует существующая политика согласования
метаданных общего ассета; новая загрузка не переименовывает чужие вложения молча.
Он использует существующее сохранение WebP без изменения размеров и lossless
преобразование остальных поддерживаемых форматов. Обрезка, уменьшение, распознавание
и цветовые эффекты принадлежат скрипту. Исходный скриншот можно обработать в памяти
и загрузить только результат; сохранять исходник обязательно не требуется.

Чтение доступно для ссылок из сохранённого стейта этой заметки и ещё действующих
загрузок этого представления. Произвольный ID другого ассета через API не открывается.
При записи неизвестная или недоступная ссылка отклоняется.

Жизненный цикл изображения:

1. Загрузка сохраняет проверенные байты и создаёт временное удержание. Отсутствие
   ссылки в стейте в этот момент ещё не разрешает удалить файл.
2. Успешная запись ссылки создаёт постоянное владение заметкой. Соответствующее
   удержание загрузки больше не нужно; другие активные потребители сохраняются.
3. Замена или удаление последней ссылки из стейта делает изображение кандидатом
   на очистку, если нет других владельцев.
4. Незавершённая либо ненужная загрузка освобождается через `release`, при
   размонтировании или восстановлении после завершения/аварии сессии.
5. Физическая очистка происходит только после проверки всех удерживающих причин.

Проверяются ссылки обычных и смарт-заметок, обложки, иконки, незавершённые операции,
активные удержания загрузок и URL, доступный undo, конфликты/recovery и журнал
публикации. Очистка в одной вкладке не должна удалять живую загрузку в другой.
Освобождение владельца никогда не удаляет одинаковое изображение у другого.
При сбое после записи байтов, но до записи стейта, остаётся очищаемый orphan;
записывать стейт со ссылкой на ещё не сохранённые байты нельзя.

После окончания удержаний мусор собирается автоматически при завершении операций,
размонтировании и следующем запуске. Ошибка очистки не откатывает успешную запись
стейта; очистка повторяется позднее. Локальные файлы ожидающей публикации удаляются
только с соблюдением существующей проверки опубликованных байтов.

Обычная очистка и действие удаления локальных файлов не должны произвольно менять
неизвестную структуру стейта. Нужные ему изображения защищены, интерфейс сообщает
число сохранённых файлов. Чтобы удалить такое изображение, ссылка удаляется через
саму заметку либо удаляется вся игра. Глобальный сброс локальных правок сохраняет
свою семантику отката к опубликованному состоянию.

Байты используют текущее браузерное хранилище и его лимиты. Переезд на другое
хранилище не входит в эту функцию; ошибка нехватки места доступна скрипту через API.

## Ленивая загрузка и сборка

Сборщик обнаруживает папки смарт-заметок универсально, проверяет документы и
наличие точек входа, но не запускает программы и не понимает их предметную логику.
Статические файлы копируются с сохранением относительных путей в отдельную область
результата сборки, например `smart-notes/<note-id>/<program-hash>/`.
Хеш учитывает пути, байты файлов программы и конфигурацию её контракта/точек входа;
изменение одного стейта не меняет адреса программы.

В runtime-базу входят метаданные, стейт, ассеты и описатель файлов программы
(относительные пути, контрольные суммы, размеры), но не исходный текст скриптов,
HTML и CSS. Описатель позволяет проверять целостность и сохранять неизменные
исходные файлы при публикации, не загружая их тела в браузер заранее.

Хост использует `import()` при первом появлении превью в видимой области.
Страница загружается только при открытии. Хост не делает её preload и не импортирует
её из превью. Автор отвечает за то, чтобы собственный preview-модуль также
не импортировал модуль страницы заранее. Дополнительные ресурсы загружает сам
скрипт. Это соответствует [динамическому импорту ES-модулей](https://developer.mozilla.org/en-US/docs/Web/JavaScript/Reference/Operators/import).

Прокрутка уже смонтированного превью за экран не пересоздаёт его; смена стейта
уведомляет подписчиков без повторного `mount`. Выход со страницы игры снимает
монтирования. Закрытие большого окна очищает только его представление.
Открытое превью может оставаться смонтированным под модальным окном.

Каждый mount получает свежий scope и AbortSignal. Позднее завершение импорта
или асинхронного mount после закрытия не возвращает DOM на страницу; полученная
позднее cleanup-функция вызывается. Импортированные модули браузер может кешировать;
unmount освобождает ресурсы представления, но не обещает выгрузить модуль из кеша.

Dev-сервер и production применяют одинаковые правила. Изменение файлов в
репозитории обновляет программу при обновлении страницы в dev. Полная сборка и
сборка с кешированной оболочкой заново формируют актуальное дерево программ;
удалённые файлы не остаются в результате. Установка новых npm-пакетов для каждой
смарт-заметки и импорт внутренних модулей приложения контрактом не поддерживаются.

## Оболочка и взаимодействия

Смарт-заметка участвует в общем порядке и группах заметок игры. Хост выводит
один заголовок `h1`, ниже размещает контейнер превью. Для её изображений не
появляется дополнительная галерея вложений: их представление выбирает скрипт.
Существующие размеры и перемещение карточки сохраняются. Редактор кода/JSON,
конвертация формата и отдельная кнопка удаления для смарт-заметки не показываются.

При наличии страницы обычный клик по заголовку или неинтерактивному содержимому
превью открывает её. Клики по кнопкам, ссылкам, полям и элементам с
`data-smart-no-open`, отменённые события, выделение текста и drag не открывают
окно. Проверка учитывает путь события внутри Shadow DOM. Для собственного
управления скрипт может вызвать `api.page.open()`.

Открытие доступно с клавиатуры через кнопку внутри `h1`, визуально оформленную
как заголовок. Если страницы нет, заголовок обычный и открывающего действия нет;
превью при этом остаётся интерактивным.

Большое представление открывается поверх игры в модальном окне. Заголовок и
кнопка закрытия принадлежат хосту, остальное пространство — скрипту. Закрытие
доступно кнопкой и Escape; клик по фону не закрывает окно. Фон недоступен для
взаимодействия, прокрутка страницы блокируется, фокус удерживается внутри окна
с учётом Shadow DOM и после закрытия возвращается к инициатору. Внутренний
обработчик может потребить Escape, например для отмены собственного действия.

Импорт, отсутствие `mount` и ошибка его выполнения показываются в соответствующем
контейнере с понятным сообщением. Для сетевой ошибки доступна повторная попытка;
ошибка вычисления самого ES-модуля может требовать обновления страницы после
исправления кода. Остальная библиотека остаётся доступной. Это не гарантия
прерывания бесконечного цикла или перехвата всех произвольных ошибок скрипта.
Ошибки API возвращаются скрипту; host также показывает проблему сохранения,
не выдавая неуспешную запись за сохранённую.

## Исходное дерево, публикация и удаление

Проекция различает изменяемый `note.json` и непрозрачные файлы программы.
Изменение стейта публикует только соответствующий JSON, необходимые изменения
image assets и существующие служебные метаданные публикации.
Файлы программы проверяются по доверенному исходному commit и сохраняются
по прежним blob ID. Заново генерировать их из runtime-базы нельзя.

При переименовании игры её существующая семантика переезда папки сохраняется:
все файлы смарт-заметок перемещаются вместе с игрой с сохранением байтов. При
удалении игры удаляются все её исходные файлы, включая программы заметок;
изображения с владельцами в других играх сохраняются. История не переписывается.

Веб-правки не могут создавать смарт-заметку, менять её ID, принадлежность,
название, точки входа, версии или файлы кода. Они могут менять стейт, выведенные
ассеты, время изменения и разрешённые настройки размещения. Удаление всей игры
является явным исключением из запрета удаления заметки. Редактирование игры
сохраняет смарт-заметки, даже если обычный редактор не передал их в списке заметок.

Эти ограничения проверяются по итоговому состоянию и дельте относительно базы
во всех путях записи, включая импорт, восстановление, выборочное применение
и публикацию. Частичный выбор правок не позволяет удалить заметку отдельно
от игры. Локальное исключение из списка не трактуется как разрешение стереть код.

Stale deployment, конфликты, проверка происхождения исходного дерева, гонки
публикации и recovery сохраняют существующие гарантии. Изменение программы
в репозитории меняет её описатель и ревизию базы. Старый клиент не публикует
поверх новой программы. Если программа изменилась, несинхронизированные правки
стейта этой заметки переходят в восстанавливаемый конфликт, даже если их JSON
формально валиден. Хост не пытается угадать совместимость неизвестной структуры
и не запускает миграцию. Уже опубликованный стейт остаётся ответственностью
автора обновлённой программы. Программа с новым описателем не получает
неразрешённый локальный стейт для исполнения; host показывает конфликт.

Просмотр локальных изменений показывает экранированный JSON-diff стейта,
изменения ассетов и размещения. Он не выполняет скрипты ради показа diff.
Название берётся из `title`; содержимое не интерпретируется как Markdown, граф
или тирлист. Отдельного протокола прогресса выполнения в первой версии нет.

## Проверка требований

Постоянные тесты используют синтетические игры, стейты и программы. Реальная
база и пример Barbuta не фиксируются в тестах. Проверки конкретных build-артефактов
и содержимого реальных игровых папок допускаются только временно.

| Требование | Явная проверка |
| --- | --- |
| Полная предметная независимость | Две синтетические программы с разными JSON-структурами работают через один host без регистрации и ветвления по ID |
| Хранение в игре | JSON, вложенные JS/HTML/CSS и статические ресурсы проходят чтение и проекцию с сохранением байтов; неправильные пути и версии отклоняются |
| Заголовок и превью | Структурно один host `h1` и один preview mount на карточку, правильный порядок, отсутствие дополнительной галереи |
| Необязательная страница | Без page нет открытия; с page один modal и один page mount, повторное открытие после cleanup |
| Ленивая загрузка | При помощи подставного загрузчика проверить момент вызова preview/page и отсутствие вызова page до открытия; временно проверить реальные сетевые запросы |
| Жизненный цикл | Подписки, URL и cleanup; закрытие во время import/mount/upload; remount; отсутствие пересоздания при изменении стейта |
| Общий стейт | Запись из обоих представлений, последовательные reducer, конфликт полного set, независимость get-снимка, перезагрузка после сохранения |
| Сохранение | Отказ квоты и записи, другая вкладка, pending publication, export/import, rescue, undo; отсутствие частично применённого стейта/списка assets |
| Ссылки на изображения | Рекурсивные массивы/объекты, повторы, неверные маркеры, неизвестные и чужие ID, удаление последней ссылки |
| Сборка мусора | Ненужная загрузка, замена, ошибка сохранения, аварийный orphan, активная другая вкладка, URL, undo/recovery и ожидающая публикация; общий ассет сохраняется |
| Неизменяемость программы с сайта | Обычное сохранение, поддельный импорт, общий редактор игры и выборочная публикация не меняют/не удаляют программу или отдельную заметку |
| Удаление игры разрешено | Полное удаление и публикация всех её smart-файлов, сохранение чужих владельцев, отмена до публикации |
| Переименование игры | Переезд всех файлов программы без изменения содержимого и без оставшихся старых путей |
| Оформление и управление | CSS двух программ не влияет на соседей; кнопки/поля/drag не открывают окно, клавиатура и focus работают внутри Shadow DOM |
| Ошибки исполнения | Сбой импорта/mount и API отображается локально, сохранённые данные и другие заметки остаются доступными |
| Совместимость | Markdown, graph, tierlist, порядок/группы, размеры, обычные вложения, публикация и восстановление сохраняют поведение |

Проверить в браузере 1280 × 800 и 390 × 844: обычную и двойную ширину, пустой
и заполненный стейт, idle/hover/focus, клик, активный drag, открытое окно,
загрузку, ошибки импорта/записи/изображения и возврат фокуса. Проверить сетевую
ленивость и размеры окна непосредственно в браузере. Исполнитель и ревьюер
сверяют результат с этой спецификацией.

Перед завершением реализации выполнить подходящие постоянные тесты, проверку
исходных данных и сборку. Временные проверки инфраструктурных артефактов удалить.
Спецификация, план, реализация и необходимые постоянные тесты составляют один
feature-коммит Jujutsu; отдельного коммита спецификации или плана нет.

## Границы работы

В работу входят общий формат, загрузчик, host, API состояния и изображений,
интеграция source/build/dev/publication/recovery и документация для автора
ванильной заметки с независимым учебным примером. Карта Barbuta и другие
пользовательские смарт-заметки создаются отдельными задачами.

Не входят редактор программ на сайте, общий каталог типов, автоматическая
конвертация существующих заметок, sandbox недоверенного кода, сервер, новая
система хранения браузерных файлов, специальная обработка карт/скриншотов,
совместное редактирование с автоматическим слиянием или универсальные миграции
предметного JSON.
