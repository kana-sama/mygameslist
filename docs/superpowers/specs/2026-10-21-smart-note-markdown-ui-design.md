# Markdown и редактор сервиса в смарт-заметках

Прямая правка пользователя: текст комнаты показывается как Markdown; отдельная
кнопка редактирования создаёт редактор. Renderer и editor предоставляет сервис
через API, без зависимости программы заметки от React/Monaco или формата базы.

## Общий контракт

```ts
api.ui.markdown(target: HTMLElement, options: {
  value: string;
  onChange?: (value: string) => void;
}): { update(value: string): void; dispose(): void };

api.ui.editor(target: HTMLElement, options: {
  value: string;
  onChange: (value: string) => void;
  onBlur?: () => void;
  onSubmit?: () => void;
  onCancel?: () => void;
  autoFocus?: boolean;
}): { update(value: string): void; focus(): void; dispose(): void };
```

- Использовать существующие MarkdownView и ленивый MonacoNoteEditor со штатной
  подсветкой, списками, таблицами и ссылками. Не писать второй renderer/editor.
- UI монтируется только в переданный контейнер текущего mount. Компоненты
  сохраняют React-контекст сервиса, корректно стилизованы внутри Shadow DOM
  и изолированы от CSS программы заметки. Monaco загружается при создании editor.
- update не должен терять выделение/undo или генерировать onChange для того же
  значения. dispose идемпотентен; scope cleanup снимает оставшиеся UI/ресурсы.
  Закрытый scope не создаёт и не обновляет UI. Поздний lazy import не возвращает UI.
- onChange передаёт исходный Markdown, не сохраняет произвольный стейт за автора.
  При наличии onChange штатные интерактивные задачи Markdown могут менять текст.
- Доступные списки игр/контекст редактора предоставляет хост. Загрузка файлов
  через редактор не входит в этот контракт; assets API остаётся отдельным.
- Набор Markdown, включая `/`, и обработанные редактором клавиши не должны
  перехватываться глобальным поиском из-за retargeting в Shadow DOM.
- state API и beforeClose сохраняют свою семантику. Хост не знает о комнатах.

## Barbuta

- Вместо постоянно видимого textarea — Markdown и кнопка «Редактировать».
  Пустая заметка показывает компактное «Заметки пока нет» с той же кнопкой.
- Нажатие создаёт штатный editor в сайдбаре; кнопка меняется на «Готово».
  Готово/Ctrl+Enter/Escape возвращают Markdown без отмены автосохранённых правок.
- Сохранить debounce 400ms, черновики по комнатам, защиту от старых подписок,
  flush при blur/смене комнаты/Готово/закрытии окна и повтор при ошибке.
- При смене комнаты удалить старый editor и показать Markdown новой комнаты.
  Ошибка записи при Готово сохраняет editor и черновик до успешного повтора.
- Не менять карту, импорт, миникарту, выделение и компоновку у краёв окна.

## Проверка

Синтетические постоянные тесты общего API: реальный renderer, callbacks,
обновление, владение mount, изоляция CSS, cleanup/abort и lazy editor lifecycle.
Проверить существующие generic smart-note тесты и editor/Markdown контракты.
Для Barbuta — временные проверки переключений и ошибок, браузерные 1280×800 и
390×844: просмотр Markdown, создание editor только по кнопке, набор/курсор,
Готово/Escape, закрытие и reload с сохранением. Не добавлять database-specific tests.
