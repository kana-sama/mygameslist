# Barbuta: чтение консольного файла в Safari

Пользователь повторно получает «Не удалось прочитать изображение» и
`WebKitBlobResource error 1` при выборе оригинального консольного JPEG.
В native Safari 27.0 воспроизведено на
`/Users/kana/Desktop/Album/UFO 50/2026102113244800_c.jpg`: прямой object URL
исходного File вызывает Image.onerror, но `file.arrayBuffer()` читает все
265728 байт; object URL нового Blob из этих байтов и FileReader data URL
декодируются как 1280×720. Диагностика с параллельными чтениями недостаточна:
после одного memory Blob исправления полный UI-импорт всё ещё выдавал ошибку
arrayBuffer. В изолированном одиночном extract без очистки input пользователь
подтвердил успешное чтение оригинала (4,3 и размер результата). Ранее проверенная
копия в /private/tmp не покрывала этот случай. Исправляется доступ к файлу и
время жизни выбора; содержимое JPEG и вырезка корректны.

## Контракт исправления

- Перед DOM-декодированием материализовать байты каждого исходного файла
  через arrayBuffer и создать object URL только для нового Blob из памяти.
- Не очищать input, пока его выбранные файлы ещё находятся в очереди.
  Удерживать исходный FileList каждой выбранной пачки до завершения импорта;
  повторный выбор во время busy должен дождаться той же очереди. Завершение
  предыдущей пачки не должно очищать более новый выбор. Повторный импорт
  того же файла после завершения должен работать.
- Сохранить лимит 40 МБ и последовательный импорт: в память материализуется
  только обрабатываемый файл, а не вся пачка сразу.
- Ошибку чтения файла отличать от ошибки декодирования. Ошибка одного файла
  не прерывает оставшуюся очередь. URL освобождается при успехе и любой ошибке.
- Не менять crop, определение позиции по миникарте, результат 256×184,
  lossless-кодирование, стейт, API, интерфейс и оформление.
- Проверить реальный оригинальный JPEG в native Safari через picker и
  повторный выбор. Очередь пачек с повреждённым файлом и перекрывающимися
  выборами проверить через полностью смонтированную заметку с purpose-built
  фикстурами. Purpose-built проверки
  disk-backed отказа, памяти, read/decode/crop/encode ошибок временные:
  database-specific тесты не добавлять в репозиторий.
