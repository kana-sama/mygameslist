# Стабильная геометрия раскрытой смарт-заметки

Пользователь предоставил запись открытия, где промежуточные кнопки и карта меньше
следующего кадра. Нормативная запись:
`/Users/kana/Desktop/Screen Recording 2026-10-22 at 05.17.19.mov`.
Извлечённые кадры: `/private/tmp/smart-note-open-frames/frame-01.png`…`frame-04.png`.

Диагноз: на промежуточных кадрах готовое содержимое соседствует со строкой загрузки
в flex-потоке. Она отнимает высоту до React commit. После её удаления fitMap заново
увеличивает карту. Из записи: высота меняется примерно на 39 экранных пикселей,
ширина карты на 55; отношение совпадает с 32/23 в расчёте fitMap.

- Индикатор загрузки page не должен отнимать место у mount. Доступная геометрия
  одинакова во время загрузки и после неё, независимо от момента React commit.
- Первый видимый кадр должен иметь окончательные размеры карты, кнопок и sidebar.
  Готовое оформление и структура из последнего кадра остаются прежними.
- Исправление общее, без специальных условий под Barbuta; сохранить CSS gating,
  preview lazy loading, скрытие/inert, ошибки/retry и cleanup текущего хоста.
- Исправить структурную причину, без таймеров и анимации, маскирующих скачок.
- Не менять authored scripts, state, API, импорт изображений или готовый дизайн.

Проверка: напрямую сравнить кадры 02/03 с 04; браузерные измерения фактической
страницы при холодном/повторном открытии. Дополнительно проверить loader в
промежуточном состоянии React: он может присутствовать в DOM одновременно с
готовым содержимым, но не меняет доступные размеры. Desktop и mobile; focused
host tests и build. Для authored страницы только временные проверки.
