## Подтверждённый баг

При включённом фильтре на странице игры полностью завершённая последняя секция остаётся видимой, если за ней находится терминальный блок определений rich tooltips. Её checked-пункты скрыты, но заголовок сохраняется. В свёрнутом состоянии это выглядит как завершённая секция `3/3` с подписью `Свернуто · 0 пунктов внутри`.

Причина — несовпадающие входные данные двух путей:

1. `InlineNoteCard` в `src/pages/GamePage.tsx:969` создаёт кэшированный snapshot через `createCompletedChecklistFilterSnapshot(parseMarkdownBlocks(note.bodyMarkdown))`, включая terminal definitions.
2. `MarkdownView` в `src/components/Markdown.tsx:1521` распознаёт определения и передаёт в рендерер только `richTooltipParsed.visibleMarkdown` (строка 1566).
3. `parseMarkdownBlocks` не извлекает rich-tooltip definitions. Например, `[?Sheba's Dream]:` с началом тела оказывается обычным paragraph после списка последней секции.
4. `blockChecklistHideAnalysis` в `src/components/markdownCompletedChecklistFilter.ts:81` обоснованно запрещает скрывать обычный paragraph. `sectionCanHide` на строке 139 оставляет содержащую его секцию видимой.
5. Переданный страницей snapshot имеет приоритет над локальным расчётом в `MarkdownRenderBody` (`src/components/Markdown.tsx:738`). Поэтому корректно подготовленный видимый текст не исправляет уже принятое решение фильтра.

Связь с последней позицией косвенная: определения лежат в конце файла и попадают в диапазон последнего заголовка. Ошибки завершения цикла на конце файла не обнаружено. Последняя завершённая секция без definitions скрывается корректно. Вложенные последние секции и их завершённые предки могут затрагиваться по той же причине.

## Предлагаемый контракт исправления

1. Snapshot обычной заметки рассчитывается по тому же `visibleMarkdown`, который показывает `MarkdownView` при включённых rich tooltips.
2. Используется существующий `parseMarkdownRichTooltips`; дополнительное распознавание definitions регулярными выражениями не вводится. Нераспознанные или прерванные definitions, которые рендерер оставляет видимыми, продолжают влиять на фильтр как обычный Markdown.
3. Для карточек `legacy-review:` rich tooltips отключены: snapshot продолжает использовать полный исходник, как и рендерер.
4. Терминальные определения не являются обычным видимым содержимым последней секции. Реальный видимый paragraph, quote, code block, обычный пункт, unchecked или indeterminate задача сохраняют прежние правила видимости.
5. Сохраняются lifecycle snapshot по generation/revision, заморозка во время активности, временное раскрытие, collapse state, structural IDs и существующее поведение таблиц.
6. Исходник заметки, определения, их порядок и содержимое, hierarchy и авторский порядок секций не меняются. Исправление не требует правок данных или CSS.
7. На примере пользователя после свежего расчёта фильтра остаются четыре незавершённые секции в прежнем порядке: Argentum Trade Guild, First Low Orbit Station, Kingdom of Tantal, Leftherian Archipelago. Spirit Crucible Elpys скрывается; единственная сводка прямых дочерних секций показывает `Скрыто 8 секций`; общий прогресс остаётся `58/66`.
8. Нажатие сводки раскрывает скрытые секции по прежнему контракту, сохраняя независимое скрытие checked-пунктов; определения продолжают открываться через существующие triggers после раскрытия соответствующих пунктов.

## Проверка требований

| Требование | Проверка |
| --- | --- |
| 1, 4 | Generic regression на `GamePage`: последняя завершённая секция с terminal definition; контрпримеры с видимым paragraph, unchecked и indeterminate |
| 2 | Generic прерванное definition остаётся обычным видимым содержимым |
| 3 | Generic legacy-review с тем же исходником сохраняет секцию |
| 5 | Существующие UI-тесты snapshot lifecycle и фильтра таблиц; generic nested heading fixture; раскрытие и отключение фильтра |
| 6 | Отсутствие вызовов persistence при фильтрации и раскрытии; существующие source-preservation tests; `jj diff` без изменений data и CSS |
| 7 | Временная проверка пользовательского вложения, без permanent data-specific assertions; один title owner и ровно одна сводка его прямых скрытых секций |
| 8 | Generic UI interaction: раскрыть секцию, раскрыть её пункты, открыть tooltip; сохранение прежнего collapse state |

При реализации implementer и reviewer должны непосредственно сравнить результат с указанным исходником, снимком и этими контрактами. На снимке показано только collapsed idle-состояние: его воспроизведение обязательно; дополнительно проверяются expanded, reveal, filter-off и существующие hover/focus состояния сводок. Новые визуальные свойства не проектируются.
