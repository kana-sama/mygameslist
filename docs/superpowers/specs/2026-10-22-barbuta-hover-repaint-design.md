# Barbuta: hover без остаточных линий

Пользовательский пример:
`/var/folders/y9/2hndrhd56jsgd181g052xf7w0000gn/T/TemporaryItems/NSIRD_screencaptureui_etlfJA/Screenshot 2026-10-22 at 06.27.14.png`.

В Safari после ухода указателя иногда остаются светлые линии рамки ячейки;
следующее наведение или перерисовка убирает их. Это происходит в превью и
большом окне. Пользователь запретил открывать Safari и проверит результат сам.

Общая рамка `button.cell::after` меняет цвет без изменений DOM. Сетка имеет
дробные размеры, а ячейки обрезают содержимое через `overflow:hidden`.
Рабочая гипотеза — неполное обновление растровой области hover-рамки WebKit.
Это не подтверждённая диагностика конкретной версии Safari.

- Дать рамке постоянный отдельный слой через `translateZ(0)` на `::after`,
  чтобы её отрисовка не делила растровую область с содержимым сетки.
- Сохранить существующие внутренние 2px рамки, цвета, порядок
  hover → linked → focus → selected, геометрию и взаимодействия.
- Применить общим CSS к превью, полноэкранной карте и особым комнатам.
- Не менять изображения, импорт, стейт или код сервиса; не добавлять
  таймеры перерисовки и постоянные тесты содержимого конкретной игры.

Проверки: diff подтверждает единственную декларацию на общем селекторе;
валидатор данных подтверждает целостность заметки. В Safari пользователь
проверяет быстрые переходы между соседними и крайними ячейками, уход с карты,
клавиатурный фокус, выбранную и связанную комнаты в обоих режимах.
