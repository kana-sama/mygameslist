# Сохранять текст комнаты после паузы

Пользователь подтвердил исправление фокуса Safari, но ввод тормозит из-за
немедленной полной записи стейта на каждый символ. Последняя правка заменяет
требование сохранять каждый input для текста комнаты; API записи остаётся
немедленным и durable для каждого совершённого вызова.

- Текст и курсор обновляются сразу в нативном textarea. Ввод не вызывает
  state.update и перерисовку карты на каждый символ.
- После 400ms без ввода отправить накопленные изменения текста одним reducer
  поверх самого свежего стейта. Флаг разгадки и работа с изображениями остаются
  немедленными. Не перезаписывать параллельные изменения других полей.
- При blur, смене комнаты и обычном закрытии окна сбросить ожидание паузы.
  Хранить черновики по комнатам до подтверждения записи; быстрое переключение
  обратно и входящие подписки не должны затирать черновик или курсор.
- Закрытие крестиком, Escape и api.page.close() ждёт завершения накопленных
  записей. Для этого добавить общий lifecycle api.page.beforeClose(handler)
  с отпиской; хост не знает про комнаты, текст, таймеры или формат стейта.
  Слушатели привязаны к scope. Без слушателей закрытие остаётся немедленным.
- Ошибка сохранения оставляет окно и черновик открытыми, показывает ошибку
  и позволяет повторить. Повторные запросы закрытия не запускают параллельный flush.
- Принудительное размонтирование, конфликт, смена программы и закрытие вкладки
  сохраняют прежнюю семантику abort; beforeClose — lifecycle обычного закрытия
  окна, а не обещание асинхронной записи после завершения браузера.
- Сохранить установленную компоновку и абстракцию произвольных vanilla-модулей.

Проверить debounce, быстрые переходы, новые символы во время записи, ошибки
и повтор, закрытие всеми тремя путями и очистку слушателей. Постоянные тесты
общего хоста/runtime используют синтетические заметки; проверки authored
Barbuta временные. Финально проверить реальный ввод и открытие после закрытия.
