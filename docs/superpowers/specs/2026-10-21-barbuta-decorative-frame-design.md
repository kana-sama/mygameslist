# Barbuta: отступы и игровые детали без рамки карты

Пользователь считает прошлую стилизацию слишком скупой и прямо требует отступов
слева и снизу, а также более заметных игровых деталей. Это заменяет прежний
контракт edge-layout/compact-polish о нулевых внешних отступах карты.

- Добавить равномерный компактный внешний отступ рабочей области: 12px desktop,
  8px на узкой вертикальной компоновке. Карта не касается левого/нижнего края.
- После следующего уточнения пользователь потребовал убрать рамку в обоих
  представлениях. Карта и превью без рамки, канта, орнамента по периметру,
  угловых креплений и периметральной тени. Внешние отступы остаются.
- Добавить глубину пустым клеткам и мелкие пиксельные детали, сохранив спокойный
  фон для реальных скринов. Внутреннее цельное выделение ячейки сохраняется;
  декоративные элементы не перехватывают pointer events и не закрывают картинку.
- Сайдбар оформить как согласованный игровой блок: выразительная кнопка импорта
  с маленькой пиксельной иконкой, аккуратный картридж координаты комнаты,
  рамка изображения с угловыми деталями, панель заметки с иерархией и отступами.
  Палитра исходника: чёрный, кремовый, розово-красный; оливковый второстепенный.
- Сохранить весь существующий текст и действия. Не добавлять статистику, легенду,
  footer, повторный заголовок игры, пример или второе fullscreen-окно.
- Пересчитать fitMap по доступному месту с учётом внешних отступов, ширины
  контейнеров и промежутка до сайдбара. Все 64 ячейки и изображение/короткий
  Markdown или редактор помещаются при 1280×800 и 1600×900 без прокрутки окна.
  Сайдбар получает остаток ширины. На 390×844 сохранить вертикальную компоновку
  без горизонтальной прокрутки; декор/изображение/редактор компактнее.
- Превью остаётся без рамки и общей шириной не более 350px. Сохраняются сетка
  8×8, пропорции ячейки 32:23, порядок и взаимодействия.
- Менять только CSS и расчёт геометрии в page.js. Не менять импорт/FileList,
  сохранение/400ms debounce, стейт, assets, crop, Markdown/editor API или сервис.
