## Platform

web

## Users

Основной пользователь — владелец конкретного развёртывания библиотеки. Он пользуется сервисом с разных устройств, чтобы вести собственную коллекцию игр, выбирать, во что играть, ранжировать игры и сохранять связанные с ними заметки и материалы.

Остальные посетители могут просматривать опубликованную библиотеку и делать локальные правки в своём браузере. Они не могут публиковать изменения в исходный репозиторий без собственных прав записи, но могут форкнуть проект и вести независимую библиотеку в своём развёртывании.

## Product Purpose

«Моя игровая библиотека» объединяет личный каталог игр, тирлист, статусы прохождения, платформы, теги, поиск, заметки, чеклисты и вложения. Продукт помогает сохранять историю игрового опыта, поддерживать бэклог в порядке и быстро выбирать следующую игру.

Успех означает, что опубликованная библиотека остаётся доступной с любого устройства, повседневные правки безопасно накапливаются локально, а владелец может осознанно проверить и опубликовать их без отдельного серверного приложения.

## Positioning

Это статическая, форкабельная и локально редактируемая персональная библиотека: текущий GitHub Pages URL определяет репозиторий развёртывания, браузер хранит неопубликованные изменения как отдельный патч, а публикация превращает проверенные изменения и новые файлы в коммит GitHub. Один и тот же клиент остаётся публичным каталогом для зрителей, редактором для локальных экспериментов и инструментом публикации для владельца репозитория.

## Operating Context

- Опубликованное состояние читается со статического GitHub Pages-сайта и доступно с разных устройств.
- Неопубликованные правки принадлежат конкретному браузеру. Для переноса и восстановления предусмотрены экспорт и импорт резервной копии патча.
- Владелец просматривает локальный diff и публикует его в репозиторий, соответствующий текущему GitHub Pages URL, с помощью fine-grained GitHub PAT с правом записи содержимого.
- Посетитель без прав записи может пользоваться интерфейсом и редактировать данные локально; для собственной публикуемой библиотеки он форкает проект и открывает своё Pages-развёртывание.
- Основные рабочие поверхности — тирлист, каталог, глобальный поиск, карточка игры и окно локальных правок/синхронизации.

## Capabilities and Constraints

- Статическое React/Vite-приложение без серверной базы, пользовательских аккаунтов и собственного backend.
- Репозиторий и владелец публикации должны выводиться из URL текущего GitHub Pages-развёртывания, а не быть зафиксированы под одного владельца в коде.
- Публикация требует действительных прав записи в выведенный репозиторий; наличие интерфейса локального редактирования само по себе таких прав не даёт.
- Опубликованные данные находятся в `public/data/library.json`, а вложения — в `public/media` по content-addressed SHA-256-путям.
- Локальные метаданные хранятся как проверяемый патч; новые вложения до публикации остаются локальными и ограничены доступным хранилищем браузера.
- Синхронизация не должна выполнять force push и должна обнаруживать расхождения с актуальным опубликованным состоянием.
- Интерфейс может оставаться полностью русскоязычным.

## Brand Commitments

- Основной язык продукта и интерфейса — русский.
- Рабочее название — «Моя игровая библиотека» / My Game Library; отдельный ребрендинг не является частью инициализации.

## Evidence on Hand

- `public/data/library.json` содержит реальную опубликованную коллекцию: 304 игры, 208 заметок и 369 записей вложений на момент инициализации.
- `public/media` содержит реальные обложки, изображения, видео и другие материалы библиотеки.
- `README.md` описывает локальный патч, GitHub-публикацию, резервное копирование и ограничения браузерного хранилища.
- В проекте нет оснований придумывать отзывы пользователей, клиентские логотипы, коммерческие показатели или другие внешние доказательства.

## Product Principles

1. **Владелец контролирует публикацию.** Просмотр и локальное редактирование открыты, но изменение общего опубликованного состояния всегда требует явных прав на репозиторий.
2. **Сначала безопасная локальная правка.** Каждое изменение можно проверить, отменить, экспортировать и согласовать с актуальной базой до публикации.
3. **Развёртывание определяет принадлежность.** Один форкабельный клиент адаптируется к репозиторию своего GitHub Pages URL и не несёт скрытой привязки к исходному владельцу.
4. **Личная коллекция важнее универсальной платформы.** Интерфейс оптимизируется под быстрый доступ к большой библиотеке, ранжирование, заметки и повторяющиеся действия одного владельца.
5. **Реальные данные не подменяются демонстрационными заявлениями.** Проект опирается на фактическую библиотеку и её материалы, не изобретая социальное доказательство или продуктовые обещания.
