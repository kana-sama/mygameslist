# Моя игровая библиотека

Статичный сайт для личной базы игр: тирлист, каталог, теги, заметки и локальные
правки без сервера. Исходники лежат в `data/`: у каждой игры своя папка с
`game.yaml`, Markdown-заметками и принадлежащими игре ассетами. При сборке они
превращаются в один `data/library.json` и дедуплицированный каталог `media/`.
Незакоммиченные изменения хранятся только в браузере.

Стартовая база пустая. Игры добавляются через интерфейс, а изменения попадают в
локальный патч. На странице игры поля и заметки редактируются на месте;
изображения в заметки вставляются из буфера обмена или перетаскиваются прямо в
Markdown-поле. Компактная кнопка `+` в редакторе добавляет изображения и
произвольные файлы; до публикации их содержимое остаётся частью локального
патча.

## Разработка

Требуется Node.js 22.13 или новее.

```sh
npm ci
npm run dev
```

Проверки:

```sh
npm test
npm run data:validate
npm run build
```

Заметка хранит YAML-метаданные в скрытом HTML-комментарии, поэтому её обычный
Markdown красиво читается на GitHub. В конце файла генератор добавляет видимый
раздел «Вложения» с изображениями, файлами и внешними ссылками; в runtime этот
служебный список не входит в текст заметки.

Одноразовый инструмент `npm run data:migrate-source -- <аргументы>` нужен только
для переноса или восстановления старой aggregate-базы. В актуальном `main` его
legacy-входов уже нет.

## Публикация данных

Публикация выполняется кнопкой **Синхронизировать** вверху окна «Локальные правки».
При первом запуске она предлагает создать и вставить fine-grained PAT:

- resource owner: `kana-sama`;
- repository access: только `mygameslist`;
- repository permission: только `Contents: write`;
- срок действия лучше ограничить.

Страница публикует изменившиеся игровые папки через GitHub Git Database API,
загружает только новые байты и обновляет `main` с `force: false`. Если Pages
показывает не тот commit, публикация останавливается как stale вместо скрытого
rebase. После коммита durable journal блокирует повторную публикацию до проверки
Pages; при более новом descendant состояние либо безопасно согласуется, либо
переходит в экспортируемый recovery-flow. Локальные копии файлов удаляются
только после проверки опубликованных SHA-256.

GitHub не умеет ограничить fine-grained PAT отдельной папкой: клиентский
allowlist защищает от ошибок приложения, но не ограничивает украденный токен.
Для защиты истории дополнительно запретите force push для `main` через branch
ruleset. Даже без ruleset само приложение никогда не отправляет `force: true`.
Запомненный PAT хранится отдельно от патча в `localStorage`; без флажка
«Запомнить» — только в `sessionStorage`. Его можно удалить кнопкой
«Отключить», а при подозрении на утечку нужно отозвать в настройках GitHub.

## GitHub Pages

Workflow находится в `.github/workflows/deploy.yml`. После добавления remote
выберите в настройках репозитория **Settings → Pages → Source → GitHub Actions**.
Каждый ручной push в `main` проверит проект, соберёт `dist` и опубликует его.
После первого push полезно открыть несколько `data/games/**/notes/*.md` по
неизменяемому commit SHA: метаданные должны быть скрыты, а раздел вложений —
виден и вести к соседним файлам.

## Safari и резервные копии

Локальный патч не синхронизируется между устройствами и может быть удалён
браузером. Окно diff показывает консервативный Safari-бюджет в 4 MiB и позволяет
в любой момент скачать patch-файл. Его можно сохранить как резервную копию и
позже восстановить через действие «Импортировать» в окне «Локальные правки».
Обложки кадрируются до 512×512 и кодируются
в WebP. Изображения в заметках сохраняют исходные пиксельные размеры: готовый
WebP сохраняется как есть, остальные форматы кодируются в lossless WebP.
